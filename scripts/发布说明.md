# 发布说明（维护者）

将 **文档转 Markdown** 源码发布到 GitHub，并让用户从 Releases 下载 exe。

> **安全提示：** GitHub 已不支持用「账号 + 登录密码」推送代码。请使用浏览器授权（`gh auth login`）或个人访问令牌（PAT），**切勿**把密码写进脚本或提交到仓库。

---

## 一、首次发布（只需做一次）

### 1. 在 GitHub 创建空仓库（若尚未创建）

打开：https://github.com/new

- 仓库名：`doc2md`
- 可见性：Public（公开）
- **不要**勾选「Add a README」（本地已有）

### 2. 登录 GitHub CLI（推荐）

在仓库根目录打开 PowerShell：

```powershell
cd C:\Users\wluser\Desktop\markdown

# 若未安装 gh，先执行：
.\scripts\install-gh.ps1

# 登录（会打开浏览器，按提示授权即可）
.\tools\gh\bin\gh.exe auth login
```

选择：**GitHub.com → HTTPS → Login with a web browser**

### 3. 一键发布

```powershell
.\scripts\publish.ps1
```

脚本会自动：

1. 推送源码到 `main`
2. 推送标签 `v1.7.2`
3. 上传 `dist\` 下的两个 exe 到 Releases（若本地已打包）

若本地未打包 exe，可只推送代码与标签；GitHub Actions 会在收到 `v*` 标签后自动构建并上传 exe（约 15–25 分钟）。

## 三、仅推送源码（不用脚本）

```powershell
git push -u origin main
git push origin v1.7.2
```

推送标签后，在 GitHub 仓库 **Actions** 页查看自动打包进度。

## 四、给用户看的文档（只介绍本工具）

维护以下文件即可，勿在对外文档中提及其他产品名称：

- 仓库首页：`README.md`
- 详细说明：`docs/使用说明.md`

---

## 五、更新新版本时

1. 修改 `converter.py` 中的 `APP_VERSION`
2. 同步更新 `README.md`、`docs/使用说明.md`、`scripts/publish.ps1` 中的版本号
3. 运行 `.\build.ps1` 打包（可选，Actions 也可代劳）
4. 运行 `.\scripts\publish.ps1`，或手动打新标签并推送
