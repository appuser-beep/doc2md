# 发布说明（维护者）

将 **文档转 Markdown** 源码发布到 GitHub，并让用户从 Releases 下载 exe。

> **安全提示：** GitHub 已不支持用「账号 + 登录密码」推送代码。请使用浏览器授权（`gh auth login`）或个人访问令牌（PAT），**切勿**把密码写进脚本或提交到仓库。

---

## 一、首次发布（只需做一次）

### 1. 在 GitHub 创建空仓库（若尚未创建）

打开：https://github.com/new

- 仓库名：`doc2md`
- 可见性：Public（公开）
- **不要**勾选「Add a README」（本地已有）

### 2. 登录 GitHub CLI（推荐）

在仓库根目录打开 PowerShell：

```powershell
cd C:\Users\wluser\Desktop\markdown

# 若未安装 gh，先执行：
.\scripts\install-gh.ps1

# 登录（会打开浏览器，按提示授权即可）
.\tools\gh\bin\gh.exe auth login
```

选择：**GitHub.com → HTTPS → Login with a web browser**

### 3. 一键发布

```powershell
.\scripts\publish.ps1
```

脚本会：推送 `main`、创建**新**标签（禁止 force 改签）、上传 `dist\` 下 exe 到 Releases。

## 三、更新新版本时（必做文档）

每次发版必须写清「更新了什么 / 解决了什么」：

1. 修改 `converter.py` 中的 `APP_VERSION`
2. 在 **`CHANGELOG.md` 顶部新增一节**（按现有格式：更新了什么 / 解决了什么）
3. 同步 `README.md` 当前版本横幅与版本表摘要
4. 同步 `docs/使用说明.md` 版本号与「版本更新说明」摘要表
5. 同步 `scripts/publish.ps1` 的 `$version`
6. 运行 `.\build.ps1` 打包
7. 提交并推送 `main`，再打标签 / 创建 Release；**Release 正文粘贴该版本 CHANGELOG 段落**

禁止对已发布标签使用 `git tag -f` / `push --force`。

---

## 四、仅推送源码（不用脚本）

```powershell
git push -u origin main
git push origin v1.7.11
```

将 `v1.7.11` 换成当前版本号。若标签已存在，请升版本号后新建标签，不要强制覆盖。
